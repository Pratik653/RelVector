# SQLGuard Ninja v0.1.0

First public release. This is an alpha: the API may change before 1.0.

## Highlights

* **Policy engine** for read-only, LLM-generated SQL on sqlglot 30: table and column grants,
  tenant isolation via equality pins, function and catalog rules, structural limits. Fails
  closed when analysis is incomplete.
* **Privacy pack:** explicit classification labels with deny / aggregate-only / review per
  role, JSON-path labels, small-cohort review, minimisation hints and safer alternatives.
* **Agent checkpoint:** block / review / audit modes, approvals bound to the SQL hash (single
  use, expiry, no self-approval), retry lock-out, redacted audit events. Integrations for
  LangChain, LangGraph and FastAPI.
* **Query cost:** an explainable static score, plus optional PostgreSQL `EXPLAIN (FORMAT JSON)`
  inspection that only runs on allowed SQL, in a read-only, time-limited, rolled-back
  transaction.
* **Benchmark:** corpus v1.0.0 with 530 labelled cases / 1,002 dialect evaluations; `allow`
  labels validated by execution on SQLite and PostgreSQL 16. Adapters for three existing
  open-source guards run in isolated environments.
* **CI:** `sqlninja benchmark compare` and a composite GitHub Action that fail on security,
  usability, error and label-change regressions against a baseline taken from the base branch.

## Known limitations

Writes are denied; restricted-function and system-catalog benchmark cases are not included;
only PostgreSQL and SQLite are tested; the native benchmark score reflects a corpus developed
together with the engine. See `KNOWN_LIMITATIONS.md`.
